# Screen Mirror 0.5.0 — iPhone → Samsung по домашней Wi-Fi сети

Приложение и ReplayKit Broadcast Upload Extension. Пользователь подтвердил
работающее изображение в 0.4.1. Новая 0.5 добавляет сохранение и подключение без
ручного набора адреса; аппаратная проверка этой версии ещё не выполнена.

Нет рекламы, подписок, аккаунтов, внешних серверов и собственного лимита времени.
Ограничения бесплатной подписи Apple (обычно 7 дней), ReplayKit/DRM и возможности
телевизора остаются. Звук передаётся только если audioApp предоставлен ReplayKit.

## Установка

1. Откройте `ScreenMirror.xcodeproj` на Mac в Xcode, поддерживающем iOS телефона.
2. В Build Settings **проекта** задайте `MIRROR_BUNDLE_ID` как прежде. В обоих targets
   ScreenMirror / Broadcast выберите свою Team с автоматической подписью.
3. Установите поверх старого приложения, предварительно остановив broadcast.
   Удаление приложения удалит сохранённые настройки. Версия внизу главного экрана:
   **0.5.0 (8)**. App Group не нужен.
4. Разрешите локальную сеть; для QR разрешите камеру. TV и iPhone — одна домашняя
   сеть без guest/client isolation и VPN.

## Подключение и запуск

- Нажмите «Найти телевизор». Используется multicast и directed unicast SSDP по Wi-Fi.
  На бесплатной подписи multicast может быть недоступен, а unicast требует ответа
  прошивки телевизора. Это реальный поиск, не список заранее известных моделей.
- Если поиска нет: `python3 tools/Pair-TV.py` на Mac в той же сети. Помощник создаст
  QR на рабочем столе. На iPhone: «Другой телевизор» → «Подключить по QR-коду».
- Ручной полный URL device description оставлен в расширенных способах подключения.
  Из предыдущего испытания пользователя: `http://192.168.31.30:7676/smp_37_`.
  Адрес может измениться; он не зашит в код и не выдаётся за универсальный Samsung URL.
- После выбора TV нажмите «Начать трансляцию», затем видимую системную кнопку iOS
  и подтвердите запись. Системное подтверждение обязательно.
- Для остановки есть кнопка приложения и системный индикатор iOS.

TV и все параметры видео сохраняются автоматически. При следующем запуске
выбранный телевизор проверяется без ввода адреса. Данные старых версий 0.4.*,
которые вообще не сохранялись, автоматически восстановить невозможно.

## Качество и задержка

Аппаратный H.264 Main 3.1 / 720p либо Main 4.0 / 1080p, 15/30 FPS, 2–12 Мбит/с.
Для 1080p попробуйте 8 Мбит/с. Альбомная коррекция 0.4.1 сохранена. AAC-LC stereo
48 кГц 128 кбит/с, единая исходная шкала PTS. Портрет вписывается с полями.

Основной транспорт — прямой MPEG-TS с MIME `video/mpeg`, который TV объявил в Sink.
Сервер работает в расширении; приложение может уйти в фон. HLS оставлен опцией.
Нет ожидания полного сегмента в прямом TS; HTTP queue и cache ограничены.

Новая «Ровная подача потока» заполняет паузы TS null packets с шагом 20 мс. Encoded
video/audio не меняются; это подтверждено совпадением декодированных контрольных
сумм тестового потока. Растёт трафик Wi-Fi (примерно 1.25 * bitrate + 192 кбит/с).
Это попытка уменьшить ожидание байтового буфера TV, **не измеренное обещание**
устранения 8–15 секунд. Временной буфер встроенного Samsung DLNA-плеера через
AVTransport не настраивается. Сравните два режима при одинаковом качестве.

## Настоящие проверки

Уже выполнены здесь: Swift 6.0.3 compilation + **13 tests, 0 failures, 0 skipped**;
реальные loopback UDP/HTTP/SOAP с тестовым приёмником; 50 циклов атомарного сохранения;
production TS muxer + FFmpeg (360 кадров / 564 AAC packets); точное совпадение
видео/аудио framemd5 до и после нового pacer. Логи: `docs/test-results/`.

Не выполнены здесь: Xcode-сборка, UI/камера, iPhone permissions и новый поиск/задержка
на физическом Samsung. Эта среда Linux; успешный core test не доказывает iOS build.

На Mac перед установкой:

```sh
bash tools/verify_on_mac.sh
```

Для независимого запуска core/media tests с Swift, Python 3 и FFmpeg:

```sh
python3 tools/run_tests.py
bash tools/test_mux.sh
```

GitHub Actions workflow также собирает iOS simulator и запускает tests на macOS;
здесь он не запускался. Готовый подписанный IPA не включён.

## Ограничения и документация

- Multicast entitlement требует одобрения Apple; пустой entitlements используется
  по умолчанию. Одной замены на Discovery.entitlements недостаточно.
- Unicast поддерживается не всеми UPnP-приёмниками. Автоматический поиск ограничен
  текущим /24 IPv4 Wi-Fi; IPv6-only и поиск по всему большому VLAN не реализованы.
- QR-помощник использует Swift/Core Image на Mac. Камера и этот macOS код требуют
  отдельной аппаратной проверки; тексты pairing codes проверены core tests.
- Прямой live TS не поддерживает произвольное seek/Range. Нет обхода DRM/HDCP.
- Loopback handshake app→extension по 19191, сервер расширения по 19192; запуск
  следует готовить в приложении, а не напрямую из Control Center после его закрытия.
- Фоновый broadcast может быть завершён iOS. Автоматический повтор такого сеанса
  без нового системного подтверждения невозможен.
- Проверки не гарантируют отсутствие всех ошибок на устройстве.
