# 0.2.2 — разрыв кадров

На реальном iPhone пользователь получил ошибку «Слишком большой разрыв кадров».
Её вызывал guard duration < 3.5 в MediaPipeline. Это доказывает срабатывание
проверки сегмента, но само по себе не доказывает причину задержки IDR.

Изменено:
- Таймер кодирует последний полученный кадр при редких входных кадрах ReplayKit.
- Время повторов монотонно, привязано к исходному PTS и времени поступления кадра.
- Явный запрос IDR каждые 1,9 секунды; закрытие сегмента на IDR после 1,5 секунды
  вместо строгого ожидания ровно 2 секунд, которое могло пропустить ранний IDR.
- Сегмент >=3,5 секунды не публикуется. Следующий начинается с IDR и discontinuity.
- HLS discontinuity sequence сохраняется при удалении старых сегментов.
- При системной паузе кадры не повторяются; после возобновления нужен новый кадр.
- Версия видна в интерфейсе: 0.2.2 (4).

Проверено здесь: синтаксис Swift, plist, ссылки Xcode-проекта.
Добавлены Swift regression cases для статического кадра, IDR-графика, монотонности
PTS и discontinuity sequence. Их выполнение требует Swift compiler на Mac;
в текущей среде они не запускались. Сборка Xcode и TV-тест здесь недоступны.
